# Пользовательские истории

Формат: *Как <роль>, я хочу <действие>, чтобы <ценность>.* Критерии приёмки — проверяемые условия, по которым история считается выполненной.

---

## US-1. Регистрация

**Как** новый пользователь, **я хочу** зарегистрироваться по email и паролю, **чтобы** мои задачи хранились под моим аккаунтом.

Критерии приёмки:
- [x] Форма содержит поля «Имя», «Email», «Пароль».
- [x] Пароль короче 6 символов отклоняется с понятным сообщением.
- [x] Повторная регистрация на тот же email возвращает ошибку «Пользователь с таким email уже существует».
- [x] После успешной регистрации пользователь сразу попадает на страницу задач без отдельного входа.

## US-2. Вход

**Как** зарегистрированный пользователь, **я хочу** войти по email и паролю, **чтобы** увидеть свои задачи.

Критерии приёмки:
- [x] Неверный пароль → сообщение «Неверный email или пароль», без уточнения, что именно неверно.
- [x] Email нечувствителен к регистру.
- [x] Сессия сохраняется после перезагрузки страницы (токен в localStorage).
- [x] Кнопка «Выйти» завершает сессию и возвращает на страницу входа.

## US-3. Быстрое добавление задачи с датой словами

**Как** студент, **я хочу** написать «завтра сходить к врачу в 15:00» одной строкой, **чтобы** не заполнять отдельные поля даты и времени.

Критерии приёмки:
- [x] Из фразы извлекается срок (завтра, 15:00), а название очищается: «сходить к врачу».
- [x] Поддерживаются: «сегодня / завтра / послезавтра», «через N дней / неделю», дни недели в разных падежах («в пятницу», «до понедельника», «к четвергу»), даты «5 октября», «30.09», время «в 15:00», «в 7 вечера», «утром / вечером».
- [x] Если дата не найдена — задача создаётся без срока, текст остаётся как есть.
- [x] Числа, не являющиеся датой («прочитать 3 главы»), не искажают название.

## US-4. Предпросмотр распознавания

**Как** пользователь, **я хочу** видеть до сохранения, какую дату понял сервис, **чтобы** не получить задачу с неверным сроком.

Критерии приёмки:
- [x] Во время набора (с задержкой ~300 мс) под полем показывается очищенное название и распознанная дата.
- [x] Показываются распознанные фрагменты («распознано: «завтра», «в 15:00»»).
- [x] Если дата не распознана — явное сообщение «дата не распознана — задача будет без срока».

## US-5. Категории и приоритеты

**Как** пользователь, **я хочу** присваивать задаче категорию и приоритет, **чтобы** отделять учёбу от личных дел и видеть, что важнее.

Критерии приёмки:
- [x] Приоритет выбирается из трёх значений: низкий / средний / высокий; по умолчанию — средний.
- [x] Категория — свободный текст с автоподстановкой уже использованных категорий.
- [x] Категория и приоритет отображаются бейджами в списке.

## US-6. Управление задачей

**Как** пользователь, **я хочу** отмечать задачи выполненными, редактировать и удалять их, **чтобы** список отражал реальное положение дел.

Критерии приёмки:
- [x] Клик по кружку слева переключает статус; выполненная задача зачёркнута и приглушена.
- [x] Редактирование открывается на месте (inline): название, категория, приоритет, срок (с возможностью очистить).
- [x] Удаление требует подтверждения.
- [x] Пользователь не видит и не может изменить чужие задачи (сервер отвечает 404).

## US-7. Фокус на сегодняшнем дне

**Как** пользователь, **я хочу** одним кликом видеть задачи на сегодня и просроченные, **чтобы** понимать, чем заняться прямо сейчас.

Критерии приёмки:
- [x] Вкладки: Все / Сегодня / Просроченные / Предстоящие / Без даты / Выполненные.
- [x] Просроченные задачи выделены красным и подписаны «просрочено».
- [x] Счётчики вверху страницы («Сегодня», «Просрочено», «Выполнено», «Всего») кликабельны и переключают вкладку.
- [x] Задачи отсортированы: невыполненные с ближайшим сроком сверху, без даты — после них, выполненные — в конце.

## US-8. Поиск и фильтрация

**Как** пользователь с большим списком, **я хочу** фильтровать по категории и приоритету и искать по названию, **чтобы** быстро находить нужную задачу.

Критерии приёмки:
- [x] Фильтры комбинируются между собой и с вкладкой.
- [x] Поиск — по вхождению подстроки, без учёта регистра.
- [x] При активных фильтрах появляется кнопка «Сбросить».
- [x] Пустой результат показывает сообщение «По этим фильтрам ничего не найдено».

## US-9. Работа с телефона

**Как** студент, **я хочу** пользоваться списком с телефона, **чтобы** записывать задачи на ходу.

Критерии приёмки:
- [x] На экране шириной 360–420 px вёрстка не ломается, поля ввода занимают всю ширину.
- [x] Кнопки «Изменить» / «Удалить» видны всегда, на любой ширине экрана.

## US-10. Запуск одной командой (техническая история)

**Как** преподаватель или другой разработчик, **я хочу** запустить проект одной командой, **чтобы** проверить его без настройки окружения.

Критерии приёмки:
- [x] `docker compose up --build` поднимает фронтенд и бэкенд.
- [x] README содержит инструкцию по запуску без Docker.
- [x] CI прогоняет тесты и сборку при каждом push.
