# Ключевые пользовательские сценарии

## Сценарий 1. Первый визит и первая задача

1. Пользователь открывает сайт → не авторизован → перенаправляется на `/login`.
2. Нажимает «Зарегистрируйтесь» → форма регистрации (имя, email, пароль).
3. Отправляет форму → сервер создаёт пользователя, возвращает JWT → приложение сохраняет токен и открывает страницу задач.
4. Видит пустое состояние: «Задач пока нет. Напишите первую в поле выше — например, «завтра сходить к врачу»», и кликабельные примеры фраз.
5. Кликает пример «завтра сходить к врачу» → текст подставляется в поле → через 300 мс появляется предпросмотр: **сходить к врачу · Завтра**, «распознано: «завтра»».
6. Нажимает «Добавить» → задача появляется в списке, счётчик «Всего» = 1.

## Сценарий 2. Задача с точным временем и категорией

1. Пользователь вводит «сдать отчёт в пятницу в 15:00».
2. Предпросмотр: **сдать отчёт · Пт, 15:00**, «распознано: «в 15:00», «в пятницу»».
3. Вводит категорию «Учёба» (или выбирает из подсказок), меняет приоритет на «Высокий».
4. «Добавить» → задача в списке с бейджами «Учёба» и «Высокий», дата отображается как день недели и время.

## Сценарий 3. Дата не распознана

1. Пользователь вводит «купить молоко».
2. Предпросмотр: **купить молоко**, «дата не распознана — задача будет без срока».
3. «Добавить» → задача сохранена без срока, попадает во вкладку «Без даты».
4. Позже пользователь нажимает «Изменить», выставляет срок через поле даты-времени, «Сохранить».

## Сценарий 4. Утренний разбор дня

1. Пользователь открывает приложение → сессия жива, сразу страница задач.
2. Смотрит счётчики: «Сегодня 3», «Просрочено 1».
3. Кликает карточку «Просрочено» → вкладка «Просроченные», одна задача с красной подписью «просрочено».
4. Отмечает её выполненной (кружок) → задача зачёркнута, счётчик «Просрочено» становится 0, «Выполнено» +1.
5. Переключается на «Сегодня» → видит план на день.

## Сценарий 5. Ошибка сервера

1. Бэкенд недоступен.
2. Список задач не загружается → вместо списка сообщение «Сервер недоступен. Проверьте, что бэкенд запущен.» с кнопкой «Повторить».
3. При попытке входа — то же сообщение под формой.

## Сценарий 6. Истечение сессии

1. Токен истёк (7 дней) или удалён.
2. Любой запрос к API возвращает 401 → клиент очищает токен → пользователь перенаправляется на `/login`.
3. После входа возвращается к задачам, данные не потеряны.
