## Отчёт «заказчику» (преподавателю)

**Сделано:**
- Полноценный интерфейс на React + Tailwind: вход, регистрация, страница задач.
- Живой предпросмотр разбора текста во время набора (debounce 300 мс), подсказки-примеры для пустого состояния.
- Фильтры по сроку/категории/приоритету, поиск, счётчики, подсветка просроченных.
- 28 автотестов (pytest), CI на GitHub Actions: тесты → линт и типизация фронтенда → сборка Docker-образов.
- Docker-compose: `docker compose up --build` поднимает всё приложение на одном порту.

**Планы (после защиты / roadmap):**
- Деплой на Yandex Cloud (B-14).
- Уведомления в Telegram о задачах на сегодня (B-15).
- Повторяющиеся задачи и распознавание приоритета из текста (B-16, B-19).

**Проблемы и блокировки:**
- Локально недоступен Docker для проверки сборки образов — сборка проверяется в CI (job `docker`).
- Деплой на публичный сервер не входит в объём MVP: показывать локально либо через Docker.

## Ретроспектива

**Что прошло хорошо:**
- Типизированный API-клиент на фронтенде сразу выявил расхождения в названиях полей.
- Оптимистичные обновления (toggle, delete) — интерфейс ощущается быстрым.

**Что улучшить:**
- Нет e2e-тестов интерфейса; ручной чек-лист компенсирует, но для следующей версии стоит добавить Playwright.
- Отсутствуют миграции БД (таблицы создаются `create_all`). Для продакшена нужен Alembic.

**Действия:**
- Провести ручное тестирование по чек-листу перед демо.
- Подготовить демо-данные (5–6 задач с разными сроками), чтобы показать все вкладки.
